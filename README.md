# remote-mac — удалённое управление Mac из Windows по локальной сети

Цель: 1080p, 60 fps, минимальная задержка. VNC лагает потому, что передаёт картинку
без видеокодека. Здесь схема как у Parsec и Moonlight:

```
Mac (remote-host)                                   Windows (remote-client)
ffmpeg: avfoundation -> h264_videotoolbox (GPU)     декодер H.264 в отдельном потоке
   -> нарезка на кадры по AUD  --- TCP, H.264 --->  -> только свежий кадр -> YUV-текстура на GPU
CGEvent: мышь, клавиатура   <--- TCP, ввод -------  SDL2: окно, мышь, клавиатура, ping
```

Всё написано на Rust. Три крейта: `proto` (протокол), `host` (macOS), `client` (Windows).

## Что проверено, а что нет

| Часть | Статус |
|---|---|
| Протокол и нарезка потока на кадры | 9 автотестов проходят (`cargo test -p proto`) |
| Хост: сеть, токен, рукопожатие, Ping/Pong, отправка видео | Проверено сквозным тестом на Linux с реальным H.264-потоком (196 из 196 кадров декодируются без ошибок) |
| Хост: захват и кодирование на Mac, эмуляция ввода (CGEvent) | **Не запускалось** — писалось без доступа к Mac |
| Клиент (SDL2 + OpenH264) | **Не компилировалось** — при написании не было доступа к crates.io |

Поэтому при первой сборке на ваших машинах возможны мелкие правки: имена методов
в крейтах `core-graphics`, `openh264` и `sdl2` немного меняются между версиями.
Компилятор сам покажет места, обычно это одна-две строки.

## Mac (хост)

Нужны Apple Silicon, ffmpeg и Rust:

```sh
brew install ffmpeg rustup && rustup-init
cargo build --release -p host
./target/release/remote-host
```

Хост напечатает порт и случайный токен. Параметры: `--port`, `--token`, `--screen`,
`--width` (по умолчанию 1920), `--fps` (60), `--bitrate` (Мбит/с, 20). Список экранов:
`ffmpeg -f avfoundation -list_devices true -i ""`.

**Разрешения** (Системные настройки -> Конфиденциальность и безопасность) для программы,
из которой запускаете хост, например Terminal:

- **Запись экрана**: иначе ffmpeg выдаст чёрный экран или ошибку.
- **Универсальный доступ**: иначе мышь и клавиатура будут молча игнорироваться
  (хост напишет предупреждение при запуске).

Чтобы Mac не засыпал и не гасил экран во время работы: `caffeinate -d` в соседней вкладке.

## Windows (клиент)

Нужны Rust (toolchain MSVC), CMake (для SDL2) и NASM (для быстрого декодера OpenH264):

```powershell
winget install Rustlang.Rustup Kitware.CMake NASM.NASM
cargo build --release -p client
.\target\release\remote-client.exe 192.168.1.50 --token ТОКЕН
```

Адрес — IP Mac в локальной сети (порт по умолчанию 7878). Токен можно задать
переменной `REMOTE_TOKEN`.

В заголовке окна показываются fps декодера, fps вывода и **RTT до хоста** (тот самый пинг).

### Клавиши

- `Ctrl+Alt+G`: захват мыши и системных сочетаний (Win, Alt+Tab) окном. Повторно — отпустить.
- `Ctrl+Alt+F`: полный экран.
- `--ctrl-as-cmd`: Ctrl работает как Cmd (Ctrl+C копирует), клавиша Win — как Control.
- `--hide-cursor`: скрыть локальный курсор, оставить только курсор из видео.
- Передаются физические клавиши, поэтому раскладку выбирает Mac. Переключайте её
  сочетанием Mac (Ctrl+Space или Cmd+Space), а не Alt+Shift.

## Настройка под задержку

- Подключайте оба компьютера **по Ethernet**, с Wi-Fi будут рывки.
- Слишком высокий битрейт на слабом канале даёт лаги: начните с 20 Мбит/с и снижайте `--bitrate`.
- Если качества мало, поднимайте `--width 2560` и `--bitrate 40`.
- Задержка складывается из: захват и кодирование (~5–10 мс), сеть (<1 мс), нарезка на кадры
  (1 кадр, ~16 мс), декодирование и вывод (~5–10 мс). Ожидайте суммарно 40–60 мс до картинки.
  Ввод идёт без видеозадержки, но курсор на экране виден через видеоканал.

## Ограничения первой версии

- Трафик **не шифруется**: используйте только в доверенной локальной сети, токен защищает лишь от случайных подключений.
- Один клиент за раз. Звука нет. Буфер обмена не синхронизируется.
- Эмуляция мыши рассчитана на основной экран Mac.
- Декодер программный (OpenH264): 1080p60 он тянет на обычном процессоре. Если захотите аппаратное декодирование (D3D11VA), это следующий шаг.
- Транспорт — TCP. Для проводной сети этого хватает; при потерях пакетов следующий шаг — UDP с FEC.
